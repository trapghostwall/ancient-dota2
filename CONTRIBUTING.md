# Contributing

Thanks for improving Ancient. This is a documentation hub, not a software
release, so the contribution rules are intentionally narrow.

## Welcome contributions

- Corrections to setup, configuration, safety, or troubleshooting pages.
- Reproducible bug reports written as documentation.
- Original SVG artwork that follows the existing visual language.
- Translations, accessibility improvements, and clearer wording.
- Metadata fixes and broken-link reports.

## Not accepted

- DLLs, EXEs, installers, archives, loaders, injectors, or packed binaries.
- Game offsets, signatures, memory layouts, or anti-cheat bypass material.
- Leaked source, vendor keys, account lists, or credentials.
- Cheat-marketplace listings, referral spam, or paid support offers.
- Instructions that ask users to disable antivirus or firewall protection.

## Workflow

1. Open an issue describing the documentation problem.
2. Keep the change focused on one page or one asset.
3. Use plain language and short paragraphs.
4. Verify every relative link.
5. Describe how you checked the change.

## Style

- Use sentence case for headings.
- Prefer concrete troubleshooting steps over vague advice.
- Mark uncertain claims as uncertain.
- Use fenced code blocks for commands and paths.
- Keep the "documentation only" framing visible.
- Do not use game captures as if they were official screenshots.

## Assets

SVG is preferred. Keep text editable, avoid embedded raster images, and include a
`<title>` and `<desc>` for accessibility. Do not add artwork copied from a game
client or a vendor without a compatible license.

## Review

A maintainer may edit wording for clarity or reject a change that weakens the
safety boundaries. By contributing, you agree that your contribution is licensed
under the repository's MIT license.
